## ① 用户问题（约 40 秒）

**谁在用、发生什么**：大学生心里有点堵的时候，缺一个「不用打卡、不被评判、先被接住」的地方——现有的工具要么让你坚持打卡，要么给你打分。本周做出来的最小可验片段是「**写一写**」：记一次心情、记一件小进步，**数据真实存库、刷新不丢**。不讲大概念，只演这一条链路。

## ② 核心流程（含一次真实写入 + 刷新持久化）（约 2 分钟）

1. **开首页**：门卡一行真实数据回放（`GET /api/moods?limit=1`）——不是写死的文案。
2. **进「写一写」**：全量真实列表（心情 + 小进步），页面走 loading / error / empty / ready 四态。
3. **检查台 /check 现场写入**：点「写入测试」→ 列表**立即多一行**、「数据更新于」跳动（`POST /api/notes` 真写 PostgreSQL）。
4. **刷新页面**：刚写的那条**还在**——刷新持久化，当场可见。
5. **补一句幂等**：同一天重复提交心情 = 覆盖，不报错、不出现第二行（数据库 `unique(owner_id, date)` 兜底，产品不惩罚任何操作）。

## ③ 提示词改写过程（约 1 分钟）

用本周真实案例（Day 20 跨域排查）：同一个问题，两种问法，结果差一个数量级。

**改写前**：

> 「前端连不上后端接口，你帮我看看。」
>
> 问题：没有症状分类、没有复现步骤、没有约束——助手只能猜，我也没法判断它猜得对不对。

**改写后**：

> 「三类症状先分类：① Console 报 `No 'Access-Control-Allow-Origin'`；② Network 里根本没有这条请求；③ 请求打到自己域名返 404。我已用 `curl --noproxy '*' -H 'Origin: …'` 复现：带我们的托管域名 Origin 有 ACAO 头，带别的域名没有。初步结论：网关白名单制，不是 `*`。约束：前端零 CORS 代码、零代理，域名不许写死在代码里。请按这个结论给我验证清单。」

**改写的要点：把「看看」换成「症状分类 + 复现命令 + 已定结论 + 约束」。**
上周最花时间的正是这类「先分类再动手」的排查；值，因为它把一次 guessing 变成了一次可验证的排除法。

## ④ 验证方式（约 40 秒）

- **周验收表五项全 PASS**：schema/seed · GET/POST 公网接口 · 分层重构 · 公网检查台 URL · api-contract.md 完整性——每项都是当场复现，命令与输出在 `docs/Day21-周验收表.md`。
- **同伴交叉验证三行结论**：能否打开 / 能否真实读写 / 有无报错（模板在 `docs/Day21-同伴交叉验证.md`）。
- **任何人可自验**：打开 /check 看真实数据 → 点写入测试 → 刷新，三步都在公网上，不需要我的机器。
