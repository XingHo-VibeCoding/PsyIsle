# 心屿 · 设计规范（UI Design System v1.0）

> 2026-10-12 ｜ 与 `frontend/src/index.css` 配套
> **数值的唯一源是 `index.css` 第 1 节（设计令牌）**——本文写的是「哪个令牌用在什么场合、不许怎么用」。
> 改视觉：先改 `index.css` 令牌，再改用到它的组件；本文只在新规则出现时更新。

---

## 1. 气质：小王子的夜空

视觉上对应三样东西：**森林深处那样安静的一层绿、插画里那点星光的暖黄、一只陪着你的小角色。**
**2026-10-13 深夜定调（现行）**：首页是一整幅深青绿水彩插画（月亮 + 星 + 波浪，见 §5.4）；全站配色统一到这套夜森林绿，**旧的蜜桃橙、暖米白、暖褐投影与暖调描边整套退役，任何页面不得再出现旧的亮黄暖色**。暖黄只允许留在插画画面内部，界面元素一律走绿；**淡紫（冷调）是仅存的一处界面点缀色**。

四条使用纪律（违反任何一条，视觉就会从「治愈」滑向「花哨」）：

1. **装饰永远退到内容后面。** 装饰性渐变只出现在首页插画与门卡图标的柔光里；页面里不允许出现第二个装饰区。
2. **装饰不承载信息。** 小角色（Mascot）只陪伴不功能：不说话、不传状态、不可点、`aria-hidden` 不进无障碍树；同屏最多一只。淡紫 `--lav-300` 只画小角色身体和晕染，**禁止当文字色**；任何用户需要读到的内容都必须落在第 3 节的文字色上。
3. **越紧急越要稳。** 危机页只用夜森林绿（平静色），不用红、不用金黄、不用大图。全站禁红色警示色是产品级红线（`AGENTS.md` §9），在视觉上的落点就是：没有一种语义状态用红色表达。
4. **信息宁少勿多。** 一张卡只说一件事；能靠留白分开的就不加分隔线；新增内容先问能不能删掉一条旧的（老板 2026-10-13 晚「别堆太多信息」）。

## 2. 色彩

### 2.1 三组色阶的分工

| 色阶 | 名字 | 管什么 | 规矩 |
|---|---|---|---|
| 夜森林绿 | `--forest-*` | **动作 + 安抚**：按钮、选中态、可点链接、危机页、呼吸、页脚求助 | 700 起才可承载文字或做实底；300/500 只做边框、描边与焦点框 |
| 淡紫 | `--lav-*` | **冷调点缀**：「找方向」瓷砖、小角色的身体 | 700 起才可承载文字（对冷米白实测 6.5:1）；300 只做装饰 |

**全站只有两族色 + 一处点缀。** 首页门卡图标曾经单开一族「星黄」呼应月亮星点，2026-10-13 深夜老板要求收进夜森林绿——**同一屏里出现两套动作色，会被读成两种状态**，所以门卡图标现在与内页按钮同族（圆底 50、笔画 700）。

分工：冷米白（`--cream`/`--card`）是全站的底；夜森林绿管动作与安抚（原来「动作=橙 / 安抚=绿」两族绿橙并置，2026-10-13 深夜合并为一族，少一族色也少一处不一致）。

### 2.2 文字色：只有四档

| 令牌 | 用途 | 门槛 |
|---|---|---|
| `--ink` | 标题、电话号码 | 对所有浅底 ≥ 10:1（对冷米白 11.4:1） |
| `--ink-soft` | 正文 | ≥ 7:1（7.8:1） |
| `--ink-mute` | 次要说明、时间戳 | ≥ 4.5:1（4.8:1） |
| `--on-dark` | 深色底（按钮、按下态）上的字 | 与所在底 ≥ 4.5:1（白字压 forest-700 6.4:1） |

**验收线：正文与次要文字对所在底 ≥ 4.5:1；≥24px 或 ≥19px 加粗的大字 ≥ 3:1。** 全站实测（2026-10-12，六页 290 处文字对）0 处失败，这个数字不许回退；2026-10-13 深夜换色后按同一门槛重算，全部达标。

## 3. 排版

### 3.1 字号：全站 6 档，多一档都算违规

| 令牌 | 值（桌面） | 用在哪 |
|---|---|---|
| `--fs-display` | 34px（手机 28px） | 首页主标语；**危机页的号码** |
| `--fs-h1` | 26px（手机 22px） | 各页面标题 |
| `--fs-h2` | 20px | 区块标题 |
| `--fs-h3` | 18px | 卡片标题、安慰卡正文 |
| `--fs-body` | 16px | 正文、按钮字 |
| `--fs-meta` | 14px | 说明、时间戳、标签（**全站最小字号，13px 不许再用**） |

历史背景：改版前全站有 11 档字号，13/14/15/16 四档只差 1px、视觉上分不出层级。新页面拿不准用哪档时，从 `--fs-body` 起步，往上最多两级。

**唯一的例外**：危机页号码用 `--fs-display`，允许比页面标题大——用户可能正处于最紧张的状态，号码必须第一眼可见。

### 3.2 字重：只用 400 / 600，**禁用 500**

「Microsoft YaHei」没有 500 字重，会回退成 400——标题与正文变得同重，层级只剩字号在撑。600 在 Windows 与 iOS 上都有真实字重。历史背景：改版前全站标题用的 500，在 Windows 上全部失效。

### 3.3 行高

- 标题（h1–h3）：`--lh-title` 1.35。改版前 body 的 1.8 被标题继承，28px 标题行高 50.4px，层级被拉散。
- 正文与说明：`--lh-body` 1.8。深夜阅读、长文案，行高宁松勿紧。

## 4. 间距与形状

### 4.1 间距：4px 基准，`--sp-1` 到 `--sp-16` 十档

改版前实测出现过 15 种间距值，其中 14/18/22/26/30 都不在 4 的倍数上。**写任何 padding / margin / gap 之前，先在令牌里挑一个；挑不出合适的，说明设计本身需要重新看，而不是造一个新值。**

节奏约定：区块之间靠 `.zone` 自身上下各 20px 相互咬合（相接处 = 40px），不要另加外边距。

### 4.2 圆角：4 档

`--r-sm` 8（焦点框）｜ `--r-md` 14（列表项）｜ `--r-lg` 24（普通卡片，2026-10-13 晚从 20 提上来：「所有卡片都做大圆角」）｜ `--r-pill` 999（按钮、芯片、标签）。
改版前卡片 16px、列表项 14px 是同角色两种尺寸——同类元素永远用同一档。曾有的 `--r-xl` 28 随 bento 门卡退役（2026-10-13 深夜）。

### 4.3 阴影：暖调，禁灰黑

三档 `--sh-1/2/3`，全部带棕色调。灰黑阴影会把奶油底压脏。

## 5. 组件约束

### 5.1 按钮 `.btn`：四态必须齐

| 态 | 写法 | 视觉 |
|---|---|---|
| 默认 | — | 主 = 桃 700 + 白字；次 = 绿 50 + 绿 700 字 |
| hover | `:hover` | 主底加深一档 + 阴影升一档 |
| **active** | `:active` | 底色落到最深一档 + `translateY(1px)` |
| 禁用 | `:disabled` / `[aria-disabled]` | 透明度 0.45，去阴影去位移 |

**为什么 active 不能省**：触屏设备没有 hover。没有按下态的按钮，手指按下去毫无反应，在手机上等于「按钮是坏的」。本产品是手机 PWA，active 是必需品不是锦上添花。

新按钮一律 `btn btn-primary` / `btn btn-quiet`，不许再造按钮样式；需要第三种语义时先回来改这里。

### 5.2 芯片 `.chip`：选中态四重信号

未选 = 白底灰字；选中 = 桃 50 底 + 桃 500 描边 + 桃 700 字 + **600 字重**，并写 `aria-pressed`。底、边、字色、字重四路同时变——色盲用户也能分辨状态。

### 5.3 卡片 `.card`：能点的才浮起来

hover 上浮 + 暖色描边只挂在 `a.card` 上。纯容器卡（安慰卡、任务聚光）保持安静——它们不是入口，不该暗示可点。

### 5.4 首页场景 `.scene`（2026-10-13 深夜老板定调：整幅插画，画面完整优先）

当晚第三次定调推翻了 bento：**不要满屏格子卡片，首页整屏铺一幅大的治愈插画**（深绿森林 + 暖黄光点，AI 生成原创，不用老板参考原图——版权），功能收进屏幕边缘，参考「不背单词 / now 冥想」的克制。bento 色块瓷砖（`.card-tile` 全家）与 hero 随之退役。

规则：

- **结构**：插画铺满整屏（`object-fit: cover`）→ 上下两层黑纱压边（`--scene-veil-top/bottom`，保证可读性也让画面更沉）→ 顶部只留问候语 → 底部一排三张磨砂门卡（`.door`）。
- **导航浮在画面上**（`.app-immersive`）：浅色字；页脚在首页隐藏——危机入口由导航「求助」承担，红线不变：仍 1 次点击可达。
- **门卡**：白纸盖在画上（`--door-bg` 磨砂 + blur），边界靠磨砂不靠描边；图标 36px `--forest-50` 圆底 + `--forest-700` 笔画（与内页按钮同族色，2026-10-13 深夜由星黄收编）；标题 body 级、引导语 meta 级。
- **插画是纯装饰**：`alt=""` + `aria-hidden`，不进无障碍树；文字信息全部由真实文本承担。
- **后续要打字的页面**（如「写一写」）沿用插画时：底图调淡或加厚纱——**字永远比画重要**，对比度不过就不许上。

### 5.5 触控目标：独立控件 ≥ 44×44

- **算独立控件**：按钮、芯片、导航项、logo、页脚链接、**每一个电话号码链接**。
- **豁免**：正文句子里的行内链接（WCAG 2.5.8 inline 例外）——但要用纵向 padding 把点击区撑到 ~50px（行内元素纵向 padding 不影响排版），`index.css` 里 `.guide-foot a` 一组是现成写法。
- 改版前危机页号码链接只有 59×25，手机上根本按不准；这是全站最不能出事的一处。

### 5.6 拟人小角色 `.mascot`（2026-10-13 晚新增）

- **纯 CSS 画**：圆角块 + 渐变做身体，眼睛/腮红/微笑用定位的小元素——不引图片、不手绘 SVG。
- **只陪伴不功能**：不承载任何信息、不可点、`aria-hidden="true"` 不进无障碍树；**同屏最多一只**。
- **出场位**：占位页（居中大号 116px——页面空的时候最容易觉得被晾着；首页已改为整幅插画场景，不再放它）。
- **动效**：4s 呼吸浮动；`prefers-reduced-motion` 全局兜底会把它压停，无需单独处理。

### 5.7 复制按钮 `.copy-btn`（2026-10-13 新增，危机页名单）

危机页完整名单的每个号码右侧一个。存在的理由：手机上点号码会直接跳拨号盘，有人还没准备好被带走；**桌面浏览器里 `tel:` 链接点了没反应**，这个按钮在那台设备上是唯一有效的动作。

三个状态，缺一个用户就不知道刚才那一下生效没有：

| 状态 | 视觉 | 文案 / 图标 |
|---|---|---|
| 待复制（默认） | 白底 + `--line` 描边 + `--ink-mute` 字 | 「复制」+ Copy 图标 |
| 已复制 | `--forest-50` 底 + `--forest-500` 描边 + `--forest-700` 字 + 600 字重 | 「已复制」+ Check 图标 |
| 复制失败 | `--line-strong` 描边 + `--ink-soft` 字（**退回无彩色，禁用红色**） | 「手动复制」 |

规则：

- **不做「复制中」转圈**：写剪贴板是毫秒级的，中间态只会闪一下更晃眼（Nielsen：1 秒内完成的操作不需要进度指示）。
- **结果态停留 2.4 秒**后回到默认；连续点击时先清旧定时器再设新的，保证状态不乱跳、页面上最多一条提示。
- **失败绝不静默**：文案与页面提示条都要说「怎么办」（长按号码手动选中）。点了没反应是本产品最不能出现的反馈形态。
- **单色不成状态**：颜色之外必带字与人形图标，色盲用户同样分得清。
- **布局**：`.hotline-head` 左拨右记（号码整块可点，复制靠右），`min-height/min-width ≥ 44px`。
- 首屏紧急三号码（120/110/12356）**不加**复制按钮：最紧张的时候路径要最短，那里只留「拨打」一件事。

### 5.8 子导航 `.guide-tabs`（2026-10-14 Day 13 新增）

找方向视图内部的三页切换（行动小事 / 书影音 / 小测评）。它是页面内的层级，**不许**长成顶部主导航的样子——层级混了，用户就分不清「换地方」和「换内容」。

- **形态：下划线式 tab**，不是卡片不是芯片；选中态 = 文字变 `--ink` + 600 字重 + 底部 2px `--forest-500` 下划线，未选中 = `--ink-soft`。
- **可访问性**：容器 `role="tablist"` + `aria-label`，每项是 `NavLink`，当前项 `aria-current="page"`（读屏与 CSS 选择器共用这一个信号，不另设 class 状态）。
- 触控目标 ≥ 44×44（padding 撑起来，文字 15px）。
- 顶栏吸顶跟随：切子视图时子导航不动，用户随时能再切，不用先滚回顶部。

### 5.9 列表四态（`components/ListStates.tsx`，2026-10-14 Day 13 新增）

任何列表数据（阶段 2 起走云数据库）必须把四种状态做齐：**加载 / 错误 / 空 / 正常**。本地数据阶段由 `lib/api.ts` 的 `?listState=` 开发开关强制出前三种，生产构建里这个开关整段不存在。

| 状态 | 形态 | 红线 |
|---|---|---|
| 加载 | `.skeleton` 骨架条 × 3 + `sr-only` 文字，`role="status"` | 不用转圈动画（骨架保住布局，内容回来不跳） |
| 错误 | `.state-note`：说发生了什么 + 「和你没关系」+ `.btn-quiet` 重试，`role="alert"` | **禁红色**；重试期间按钮回到加载态，杜绝「点了没反应」 |
| 空 | `.state-note-quiet`：说清是哪个条件下没有 + 退路动作 | 不许只写「暂无数据」让用户自己猜 |
| 正常 | 列表本体 | — |

规则：

- 状态机在 `lib/useListData.ts` 一处实现，页面只认 `loading / error / empty / ready` 四个值，不许页面里各自写 useState 拼状态。
- 错误文案永远不指责任何人（写「网络不太稳」，不写「加载失败请重试」的机器腔）；空态和错误态的区别是「这不是故障」。
- 四态组件无动效依赖（骨架条只有透明度呼吸），`prefers-reduced-motion` 下自动合规。

## 6. 无障碍与动效

- **焦点**：全站统一 `:focus-visible`（3px 夜森林绿 + 2px 偏移），组件不许各自定义。
- **减少动态效果**：`prefers-reduced-motion: reduce` 下所有 transition/animation 关到 0.01ms、位移归零。用户里有相当一部分对动效敏感，这不是可选优化。
- **字号缩放**：字号用 `rem` 令牌（根字号 100%），系统调大字号时文字跟着走；间距保持 `px`，保证版心稳定。

## 7. 响应式

- **手机第一**：断点只有一个（`max-width: 600px`）。手机上只收两个字号令牌（display 34→28、h1 26→22），其余直接沿用——档位少，这是收敛字号档数的直接收益。
- **验收线**：375px 与 320px 全站无横向滚动（`document.scrollWidth ≤ viewport`）。2026-10-12 实测六页全部通过。
- 新增页面后必须复测这两条；hero 类带绝对定位装饰的容器必须 `overflow: hidden`（曾因装饰溢出把 375px 撑到 432px）。

## 8. 下次设计审查怎么查（验收清单）

1. 全站字号档数 ≤ 6，最小 14px；
2. 所有间距值是 4 的倍数；
3. 文字对比度：六页逐处计算，失败数 = 0；
4. 触控 < 44×44 的独立控件数 = 0；
5. 375 / 320px 六页 `docW ≤ vw`；
6. 按钮四态（默认 / hover / active / 禁用）在 CSS 里 grep 得到；
7. 标题字重全部 600，无 500；
8. 有反馈的交互：成功与失败两种结果都有可见反馈（文案 + 形状，不只是颜色），且「点了没反应」不出现。
9. 新增的任何列表：加载 / 错误 / 空 / 正常四态齐全，走 `useListData` 状态机；错误与空态没有红色、没有指责性文案。
10. 页内层级切换用 `.guide-tabs` 形态（下划线 + `aria-current`），不与顶部主导航撞样式。
