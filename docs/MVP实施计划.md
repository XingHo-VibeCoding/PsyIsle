## 1. 这份计划的范围

| 项 | 取值 | 依据 |
|---|---|---|
| 项目 | **心屿** | `README.md` |
| 步数 | **5 步** | 模板里的【步数】按 5 填，与前面 MVP 计划的节奏一致 |

## 2. 五步计划

### 第 1 步｜PWA 三件套：让「手机 App」这个形态成立

| | |
|---|---|
| **目标** | 手机浏览器打开 → 「添加到主屏幕」→ 有图标、全屏、断网也能开壳 |
| **改哪些文件** | 新增 `frontend/public/manifest.webmanifest`（name / short_name / start_url / display: standalone / theme_color `#FFF8F0` / background_color / icons 192+512）<br>新增 `frontend/public/icon-192.png`、`frontend/public/icon-512.png`（蜜桃橙底 + 岛屿）<br>改 `frontend/index.html`：加 `<link rel="manifest">`、`<meta name="theme-color">`、`<link rel="apple-touch-icon">` |
| **怎么跑** | `cd frontend && npm run dev -- --host`，手机与电脑连同一 Wi-Fi，浏览器开 `http://<电脑局域网IP>:5173` |
| **怎么验证** | ① 桌面 Chrome 地址栏出现「安装」图标；② DevTools → Application → Manifest 无红色报错，192/512 两个图标都能加载；③ 手机「添加到主屏幕」→ 桌面出现带图标的心屿 → 点开全屏、无地址栏；④ `npm run build` + `npm run preview` 后 ①②③ 依然成立（**PWA 装的是产物，dev 通过不算数**） |
| **这一步不碰** | 登录、云服务、AI、任何业务逻辑；一行业务代码都不写 |

> 顺带（需你点头才做）：`index.html` 的 `<title>心屿 · 你的情绪小岛</title>` 和 `public/favicon.svg` 都是 v4.0.1 时期的东西，v5.0 定位里没有「情绪小岛」这句。是否一起换成 v5.0 口径？

### 第 2 步｜指路灯 · 小测评：把「测评 → 下一步」这条主链路闭合

| | |
|---|---|
| **前置** | 必须先裁定冲突 **6**（用哪个量表、结果怎么落到 5 个主题） |
| **目标** | 做完一个测评 → 得到一段**描述**（无总分、无档位、无百分位）→ 直接落到「推荐 3 条内容 + 今天可做的 1 件小事」 |
| **改哪些文件** | 新增 `frontend/src/data/assessments.ts`（题目 + 计分区间 + **固定解读文案**）、`frontend/src/lib/score.ts`（纯函数，现算，可单测）、`frontend/src/pages/Assessment.tsx`；`App.tsx` 加路由；`pages/Guide.tsx` 把「还在准备」卡片换成真入口 |
| **怎么跑** | `npm run dev` → `/guide` → 点测评做完 |
| **怎么验证** | ① 做完得到的是一段描述，页面上搜不到总分 / 档位 / 百分位 / 位置词；② 推荐的 3 条内容确实来自 `library.ts` 且带得出「为什么给你看这个」；③ **答到一半刷新，作答还在**（草稿层红线）；④ 把解读文案抄出来逐句过一遍 `PRD.md` §4 的措辞红线 |
| **这一步不碰** | 树洞、账号、云端存储 |

### 第 3 步｜日常管家最小版（纯本地）

| | |
|---|---|
| **目标** | 记一下今天的心情（表情 + 可选一句话）和一件小进步；**一条都不记也完全正常** |
| **改哪些文件** | 新增 `frontend/src/pages/Daily.tsx`、`frontend/src/data/moods.ts`（表情与文案）；`lib/storage.ts` 扩一个按日期读写（仍包 try/catch） |
| **怎么跑** | `npm run dev` → `/daily` |
| **怎么验证** | ① 记一条 → 刷新还在；② 不写文字只选表情也能存；③ 页面上**搜不到**「连续 / 中断 / 已落后 / 排行榜」任何一个词（PRD 产品灵魂）；④ 清缓存后不白屏 |
| **这一步不碰** | 云同步、提醒推送、AI 复盘 |

### 第 4 步｜开通云服务 + 账号 + 建表（把本地数据搬上云）

| | |
|---|---|
| **前置** | `TECH_DESIGN.md` §9 的 4 项必须**核实完**（建表方式与字段类型 / 模型是否支持流式 / 支持哪些登录方式 / 免费额度与配额），不留「大概能行」 |
| **改哪些文件** | 新增 `frontend/src/lib/cloud.ts`（**唯一初始化点**，只用 `publicConfig`，禁止硬编码域名）；重写 `frontend/.env.example`（换掉 `VITE_TCB_ENV_ID`）；建 `moods` / `progress_notes` / `profiles` 三张表（按 PRD §5，**不含任何诊断性字段**） |
| **怎么跑** | `npm run dev` → 注册/登录 → 记一条心情 |
| **怎么验证** | ① 换浏览器登录后数据还在；② **用另一个账号登录看不到前一个账号的数据**（身份隔离，这是最容易出事的一条）；③ 登录态失效时保留当前页面内容；④ `.env` 未入库（`git status` 里看不到） |
| **硬门槛** | 涉及「用户数据读写 + 部署」，按开发原则：**部署前全量测试通过**，这一条不能省 |
| **这一步不碰** | 社区、AI |

### 第 5 步｜AI 树洞最小版（倾听 + 危机识别）

| | |
|---|---|
| **目标** | 能对着它说话，它只倾听、不诊断、不评价；撑不住的时候立刻浮出真实求助资源 |
| **改哪些文件** | 新增 `frontend/src/lib/crisis.ts`（**本地词表先判，不等模型**）、`frontend/src/data/safety.ts`（危机文案 / 安全提示 / 兜底文案，**全部写死**）、`frontend/src/pages/Talk.tsx`；云服务模型调用走 `lib/cloud.ts` |
| **怎么跑** | `npm run dev` → `/talk` |
| **怎么验证** | ① 准备 ≥5 条危机表达用例，**全部立刻出资源卡**，不等模型返回；② 模型超时 / 报错 / 空回复 → 固定兜底文案 + 重试，**绝不空白、绝不抛错误堆栈**；③ 「我是 AI，不是真人，也不是医生」不可关闭；④ 一键清空 = 真删；⑤ 断网时说得出去、看得到资源卡 |
| **这一步不碰** | 匿名社区（第 4 周，不在本计划） |

## 3. 五步之后

到第 5 步结束，三块各有一个能跑的最小版，加上常驻求助页 —— 这就是 MVP 的完整边界。
匿名社区（PRD §6 第 4 周）**刻意不在本计划内**：它涉及审核能力与干预责任，`PRD.md` §4.2 已写明「第 4 周开工前必须先想清楚」。
