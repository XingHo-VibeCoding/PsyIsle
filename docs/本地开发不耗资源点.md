# 本地开发：不消耗 CloudBase 资源点

> 为什么要有这份东西：账单里 **PostgreSQL 占 98.1%** 的资源点，而每次打开本地页面
> 都要打几次 `/api/moods`、`/api/notes`。**「在本地看看效果」这件事本身在烧钱。**
> 在预算见底前，日常开发一律走下面的离线路子。

## 一条命令起 mock，再一条起前端

终端 A（先起 mock）：

```bash
node scripts/mock-api.mjs
```

终端 B（前端连 mock）：

```bash
# Git Bash
VITE_API_BASE=http://localhost:5178 npm --prefix frontend run dev

# PowerShell
$env:VITE_API_BASE="http://localhost:5178"; npm --prefix frontend run dev
```

打开 `http://localhost:5173`。

**怎么确认真的没打线上**：终端 A 会逐条打印 `[mock] GET /api/moods`。
如果那边没动静而页面有数据，说明配置没生效 —— 回去检查环境变量。

## mock 里有什么

| 接口 | 说明 |
|---|---|
| `GET /api/health` | 扁平字段（契约里唯一不套信封的接口） |
| `GET /api/moods` | 游标分页，**60 天种子，能真的点「看更早的记录」** |
| `POST /api/moods` | 同日覆盖（幂等），软删的会被找回 |
| `PATCH /api/moods?id=` | 只改传进来的字段，并复位软删 |
| `DELETE /api/moods?id=` | 软删除 |
| `GET/POST /api/notes` | 同样游标分页 |
| `POST /api/claim` | `issue` 发票据 / `redeem` 换（回固定数字） |

游标语义与 `cloudfunctions/*/db.js` **完全同构**（`d=date, c=createdAt, i=id`，base64url），
所以分页顺序、去重、到底判定这些逻辑在本地验完，线上不会变。

## 什么时候**必须**去线上

mock 故意不做这三件事，它们也正是唯一值得花资源点去验的部分：

1. **网关注入身份**（`Authorization: Bearer` 校验、401 行为）
2. **RLS / 外键 / `anon` 授权**（真实写库能不能过）
3. **真实延迟与冷启动**

除此之外的一切 —— 布局、四种状态、分页翻页、表单校验、文案、路由 —— 都能在本地验完。

## 别忘了

- mock 数据在内存里，**重启就重置**。种子每次重新生成（日期按「今天往前推 60 天」）。
- `GET /api/notes` 与 `GET /api/moods` 是同一个 mock 用户，没有多账号隔离。
- 端口冲突就换：`MOCK_PORT=5179 node scripts/mock-api.mjs`，前端那边同步改。
