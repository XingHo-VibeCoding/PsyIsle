# Day 27 · 修复提示词模板（心汐）

> 用法：拿到《Day27-试用记录表.md》后——① 按 §1 选出**唯一一个**最高优先级卡点；② 照 §2 模板填成一段提示词，整段发给 AI 动手；③ 修完按 §3 给试用过的人发复验任务。
> 今天的边界：**只修这一个**，不按反馈大改、不加新功能。

## §1 选卡点：只选一个，按这个顺序判

| 级别 | 定义 | 例子 |
|---|---|---|
| **P0 阻断** | 核心流程走不下去：打不开、存不下、刷新丢、删不掉——用户原地放弃 | 第 3 步找不到记下来的入口，直接不用了 |
| **P1 误解** | 流程能走完，但理解错了产品是什么、自己的数据存在哪 | 以为记录只存在这台手机上 / 以为这是心理咨询 |
| **P2 摩擦** | 能走完，但明显犹豫、反复点、问了人 | 第 5 步找了半天才想起可以再记一次 |

排序规则：

1. 级别优先：P0 > P1 > P2；
2. 同级别比「停得最久」和「卡了几个人」；
3. 「**你自己也没想到他会卡**」的那条，权重抬高一级——没被想到的卡点，往往意味着设计者和用户之间有一堵墙；
4. 其余卡点只记录，进待办，今天不动。

## §2 修复提示词模板（照填，整段发给 AI）

```text
项目：心汐，仓库 C:\Users\24486\Desktop\工作台\心汐，环境 psyisle-prod-d9g109suw53257aed（线上在跑，改完要部署）。

【卡点】试用第 __ 步：___
【用户原话】「___」（逐字，来自记录表 §二/§三）
【现场】他做了 ___，界面显示 ___，他期望 ___，最后 ___（做成/绕开/放弃）。
【判定】P0 阻断 / P1 误解 / P2 摩擦（只修这一个）

【只改这一处】___（说清楚改哪里、改成什么样；说不清就先去页面复现，别凭猜动手）

【约束】
- 只修这一个卡点：不加新功能，不顺手改别处；发现别的问题只记录。
- 改文案先查全站称呼是否一致：导航是「听你说 / 找方向 / 写一写」，别处不能再出现「倾诉树洞 / 指路灯 / 日常管家」。
- 错误口径遵守 api-contract.md §3：输入错误透出后端中文原文；服务端错误统一「服务出了点小状况…」；响应体禁出现表名、字段名、SQL、英文堆栈。
- 全站禁红色；不引入打卡连续天数 / 排行榜 / 落后提示类机制。
- 动接口或表结构：先改 api-contract.md（契约 SSOT），再改代码。
- 身份与数据：取不到登录身份就抛 401，绝不回退默认 uid；身份变化后必须重新取数。

【自检】改完必须全过：node scripts/verify-project.mjs（15 项）、node scripts/check-error-messages.cjs、node scripts/check-secrets.cjs；前端另跑文案检查。

【交付】① 改动文件清单（每处为什么改）；② 本地构建通过；③ 一句话说明这个修复对试用链路第 __ 步的影响。
```

## §3 修复后复验最小任务（发给试用过的人，只做一件事）

```text
再帮我看 10 秒 🙏 还是那天那个链接、你那台手机：

只做一件事：___（例如「把今天的心情改成『一般』」/「把刚记的那条删掉」）。

不问人、不翻说明书，10 秒内能做到就算过。
```

判读：

- **做到了** → 修复有效，关单，把结果记进《Day27-试用记录表.md》对应行；
- **没做到** → 要他的新原话，再修一轮；**最多两轮**，还不行就记进待办，不恋战（今天还有资源检查等收尾）。

> 复验必须用**同一台设备 / 同一个浏览器**：匿名身份认设备，换设备就是另一个 uid，看不到原来的记录。
