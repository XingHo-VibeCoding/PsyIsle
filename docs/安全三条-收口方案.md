# 安全三条 · 收口方案（Day 21 收尾登记）

> 结论先行：三条红线是**同一个「接登录」工程的三个验收点**。第 ③ 条（检查台）已于 2026-10-16 下线收掉；第 ①② 条动线上数据库授权与 RLS，而云函数当前以 `anon` 身份连库、RLS 处于关闭态——**现在孤立执行会当场打挂线上演示**，必须与登录改造同一批做。本文是到时可照抄执行的方案。

## 一、线上现状（2026-10-16 只读 SQL 实测，非凭记忆）

| 项 | 现状 |
|---|---|
| RLS | `moods` / `progress_notes` = **关闭**；`profiles` = 开启 |
| RLS 策略 | `moods_owner_only` / `progress_notes_owner_only` **已写好且正确**：绑定 `{authenticated}`、`ALL`、判定 `owner_id = auth.uid()`——只差「开 RLS」一步生效 |
| anon 授权 | 对两表仍有 SELECT/INSERT/UPDATE（Day 18 演示期临时 `grant`） |
| 云函数身份 | `@cloudbase/node-sdk` 的 `app.rdb()`，底层以 `anon` 连库；写操作 owner_id 是代码里写死的演示 uid `00000000-0000-4000-8000-000000000099` |
| 检查台 | ~~公网可写~~ → **已下线**（路由/页脚/组件/ROUTES 已移除，契约 §7 已标记 ✅） |

## 二、为什么不能现在收（推演）

1. 先 `revoke anon` → 云函数（anon 身份）读写立刻全部 401/权限拒绝，首页/日常管家全挂。
2. 先 `enable row level security` → RLS 一开，anon 直连只剩策略放行的行；策略绑定的是 `authenticated` 角色，anon 请求**一行都看不到**，同样全挂。
3. 唯一安全的顺序：**先让云函数带上可信的用户身份，再关 anon、开 RLS**。这就是「接登录」。

## 三、到时的执行顺序（照此跑，每步可回退）

**阶段 A · 接登录（前端 + 云函数，代码活）**
1. 接入 CloudBase 登录（短信/微信之一），前端拿到登录态与身份凭证。
2. 云函数改为：从请求头验证登录态 → 取真实 `uid` → 用它作为 `owner_id`（替换写死的演示 uid，`moods/index.js`、`notes/index.js` 里的 TODO 标记处）。
3. 决策点：云函数连库身份二选一——
   - **方案甲（推荐）**：函数改用 `service_role` 级凭证连库，**RLS 管不到它**，owner 隔离由代码强制（owner_id 只取自已验证的登录态，绝不收客户端传入）。简单、稳，适合函数是唯一写入方的前提。
   - **方案乙**：函数透传用户身份以 `authenticated` 连库，隔离由 RLS 兜底。更纵深防御，但要打通身份透传，工作量大。

**阶段 B · 数据库收口（SQL，一次性）**
```sql
-- ① 开 RLS（策略已在库里躺好，开了即生效）
ALTER TABLE public.moods          ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.progress_notes ENABLE ROW LEVEL SECURITY;

-- ② 收回 anon 全部授权（Day 18 临时开的三样全收）
REVOKE SELECT, INSERT, UPDATE ON public.moods          FROM anon;
REVOKE SELECT, INSERT, UPDATE ON public.progress_notes FROM anon;
```
执行方式：`tcb db execute -s "<语句>"`（已验证可用），一条一条跑，跑完立即公网回归。

**阶段 C · 回归验证**
- [ ] 未登录状态：`/daily` 提示登录、接口拒绝写（anon 已无权限）
- [ ] 登录后：A 用户只能看到/写到自己的行（RLS `owner_id = auth.uid()` 生效）
- [ ] `GET /api/moods` / `notes` 登录后正常返回
- [ ] flow-test 全绿（需要按登录态改造后重跑）
- [ ] `/check` 确认仍为 404/不存在

## 四、风险与兜底

- 阶段 B 两条 SQL **可逆**（`DISABLE ROW LEVEL SECURITY` / 重新 `GRANT`），执行前先在文档里记下当前授权快照（§一表格即是）。
- 万一函数身份改造出问题导致线上挂：回退顺序 = 先恢复 anon 授权 + 关 RLS（演示立即可用），再慢慢修函数。
- 演示数据（owner 为演示 uid）在收口后只有登录该 uid 才可见；接登录时决定演示数据是迁移到真实账号还是保留公开只读。
