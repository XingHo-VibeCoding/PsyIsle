怎么读这棵树

一条主线：用户手指 → 页面（pages）→ 云函数入口层（cloudfunctions/*/index.js）→ 数据访问层（db.js）→ 数据库（CloudBase PG）→ 渲染回来。前端只经云函数读库，不直连。
cloudfunctions/ 分两层（Day 19）：入口层管「这是什么请求、参数合不合法」，数据访问层管「怎么查库」。app.rdb() 只许出现在 db.js——换库、接登录，只改那一层。
data/ 是内容层：危机号码、安慰文案、主题、小事、书影音全在这里，跟着构建一起打包，断网也在。
lib/ 是纯逻辑层：不画界面、不写死文案，只做一件事。api.ts 是前端唯一的云端出口。
components/ 是复用件：被两个以上页面用到才放这里；只用一次的留在自己页面里。
页面的三档状态写死在路由里：pages/ 下的文件名就代表做没做——占位页一律走 UnderConstruction.tsx，不做死路（能回首页、能到求助页）。

刻意不存在的目录

sql/migrations/ —— 建表不靠迁移脚本：唯一源是 db/schema.sql，在 CloudBase 控制台的 SQL 编辑器执行。

node_modules/、dist/ —— 构建产物，已进 .gitignore，不进仓库。
