怎么读这棵树

一条主线：用户手指 → 页面（pages）→ 数据（data / 本地草稿）→ 渲染回来。现在全在浏览器里，云服务阶段 2（课程 Day 13–19）才开。
data/ 是内容层：危机号码、安慰文案、主题、小事、书影音全在这里，跟着构建一起打包，断网也在。
lib/ 是纯逻辑层：不画界面、不写死文案，只做一件事（现在只装了本地存储）。
components/ 是复用件：被两个以上页面用到才放这里；只用一次的留在自己页面里。
页面的三档状态写死在路由里：pages/ 下的文件名就代表做没做——占位页一律走 UnderConstruction.tsx，不做死路（能回首页、能到求助页）。

刻意不存在的目录

cloudfunctions/、sql/migrations/ —— v2.0（CloudBase 时期）有，v3.0 取消：后端改成托管云服务，没有自建服务端代码，建表也不靠迁移脚本。

node_modules/、dist/ —— 构建产物，已进 .gitignore，不进仓库。
