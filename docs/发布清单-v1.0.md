## 三、发布步骤

固定三步，少一步就出事（顺序不能换）：

```
# 0. 在仓库根，确认工作区干净、在 v1.0.0 提交上
git status --short
git rev-parse --short HEAD          # 应为 e18b462

# 1. 构建（会清空 dist）
cd frontend
npm run build
cd ..

# 2. 补子路由 fallback（必须在 build 之后；build 会清掉 dist 里的子路由入口）
node scripts/spa-fallback.mjs

# 3. 部署并逐文件校验
tcb hosting deploy frontend/dist -e psyisle-prod-d9g109suw53257aed --verify
```

## 五、代码与数据备份方式

### 5.1 代码

| 方式 | 做什么 | 存放位置 | 恢复方法 |
|---|---|---|---|
| Git 标签 | `git tag -a v1.0.0 e18b462` | 本地 + 远程（`git push origin v1.0.0`） | `git checkout v1.0.0` |
| 远程仓库 | 全部提交已推到 `origin/main` | GitHub `XingHo-VibeCoding/PsyIsle` | `git clone` / `git fetch` |
| 产物快照 | 复制 `frontend/dist` 整目录 | `%TEMP%\psyisle-v1.0-backup\dist`（818 KB） | 直接 `tcb hosting deploy` 该目录 |
| 产物指纹 | bundle 名 + 字节数 + sha256 记在本文件 §1 | 本文件 | 比对判断线上是不是这一版 |

> 产物快照是**回滚最快的一条路**：不用重新构建，直接部署旧 dist（本次恢复 v1.0 就是这么做的，7 秒）。快照要连同 `index.html` 一起存，否则 bundle 名对不上。
