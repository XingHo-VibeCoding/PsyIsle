# 筛选交互验收 filter-audit

## 一句话
它检查「找方向」页的筛选：**勾了能看到东西、勾空了有一句明确的话、取消勾选能回到原样**，并且这一整套用键盘和读屏也能走完。

## 为什么要有它
筛选这类交互最容易只把「正常路径」测了：有结果的分支点过，空结果和清空的分支没人点——
那两个分支长期是死代码，真出问题时用户看到的是一块白，或者上一轮筛剩的条目。

这个 Skill 把三种情况钉成必测项，附上可执行的点击路径与判据，跑完一次就落一份记录，方便和上一次次对照。

## 被测对象
- 仓库：`心屿/`（本文件位于 `心屿/skills/filter-audit/`——Agent Skills 的惯例位置本是 `.workbuddy/skills/`，但本仓库已把 `.workbuddy/` 整体列为不入库的助手数据目录，而这份 Skill 是课程交付物，需要留在仓库里，所以放在 `skills/`）
- 页面：`/guide`「找方向」
- 两个筛选轴：
  - **主题**（多选；一个都不选＝不筛选，全部给你看）
  - **书影音类型**（单选：全部 / 书 / 电影 / 音乐 / 播客）

## 前置
1. `cd frontend`
2. `npm install`（首次，或 `package.json` 有变动——有声明不等于装好了）
3. `npm run dev`，记下端口（默认 5173，被占用会顺延）
4. 打开 `/guide`，先清一次 `localStorage`（键 `xinyu.guide.themes`）保证起点干净

## 检查清单

### C1 有结果
- 操作：只勾一个主题（如「孤独」）＋一个类型（如「书」）
- 通过判据：书影音区出现条目；每条都同时符合所选主题与类型；不出现空态文案
- 反例：混进不符合条件的条目；区域空白

### C2 无结果
- 操作：选一个在该类型下确实为空的组合（如 主题「孤独」＋类型「播客」）
- 通过判据：出现一句明确的空态文案（告诉人换个条件看）；上一次的结果不残留在页面上；控制台无报错
- 反例：一片空白；抛错；还显示着上一个条件的结果（最常见）

### C3 清空恢复
- 操作：类型切回「全部」，主题全部取消
- 通过判据：列表回到与第一次进页面时完全一致（条目数、顺序都一样）；不需要手动刷新
- 反例：少了或多了条目；要刷新才恢复；`localStorage` 里留下已经取消掉的脏值

### C4 可访问性（余力加练）
- 键盘：Tab 能依次走到每个筛选按钮；Enter 或空格能切换；焦点有可见轮廓
- 状态：多选按钮带 `aria-pressed`，能读出「已选中／未选中」；空态用 `role="status"`
- 触控：每个筛选按钮的命中区 ≥ 44×44
- 持久化：刷新页面后，主题的勾选状态能恢复；存的值非法（不是已知主题）时回落成空，而不是把页面搞崩

## 输出
每次调用写一份记录：`runs/YYYY-MM-DD.md`（同一天多次调用加序号）。
格式：逐项 `通过 / 失败`，失败项附现象与截图路径；最后一行写结论。
